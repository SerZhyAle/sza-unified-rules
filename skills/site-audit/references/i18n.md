# i18n lens - does every language have its own URL with reciprocal `hreflang`, or hide in one DOM?

Measures how each language the site ships reaches a crawler without JavaScript and a visitor, holds every language
declaration against the page it names, and proposes own pages for a locale meant to be found or an honest single URL
for one that is not ([PROMOTION.md](../../../rules/PROMOTION.md) §3).

## Inputs

Read first - `robot.json` per page: `lang`, `dataLang`, `langSpans`, `cyrillicChars`, `latinChars`, `textNoJs`,
`headings`, `title`, `description`, `canonical`, `metaRobots`, `hreflang` (every field), `xDefault`, `ogLocale`,
`ogLocaleAlternate`, `jsonld[].raw` (for `inLanguage`), `jsRewrites`, `scripts`, `versions`, `links.downloads`, and the
site's `sitemap`; `ux_probe.json` per page and mode, in `probe`: `lang`, `title`, `metaDesc`, `h1`, `cyrRatio`,
`hasLangSwitch`, `smallTapTargetsAboveFold`, `foldText`; and the screenshots.

Re-measure live, GET only: each `hreflang` or switch target's `<html lang>`, `dir`, first `h1` and script share
(status, canonical, `noindex` and reciprocity are in `hreflang` for its targets; for a switch target outside the set,
measure them too); the sitemap body, for its language rows and `xhtml:link` alternates; the home with `?lang=<code>`
per declared code. The script share, printed and never stored, with code, keyboard and sample text left out; for a
code in another script, its block takes the place of `\p{IsCyrillic}` (check 3):

```powershell
$t = (Invoke-WebRequest -UseBasicParsing -TimeoutSec 25 -SkipHttpErrorCheck -UserAgent 'Mozilla/5.0 (compatible; sza-site-audit/1; read-only)' -Uri '<url>').Content -replace '(?s)<(script|style|template|pre|code|kbd|samp)\b.*?</\1>', '' -replace '<[^>]+>', ' '
'cyr {0} lat {1} ru {2} uk {3}' -f [regex]::Matches($t, '\p{IsCyrillic}').Count, [regex]::Matches($t, '[A-Za-z]').Count, [regex]::Matches($t, '(?i)[\u044B\u044D\u044A\u0451]').Count, [regex]::Matches($t, '(?i)[\u0456\u0457\u0454\u0491]').Count
```

In the repository's served root: the CSS hiding inactive languages, the language classes (`.ru`, `.en`, `.uk`) that
`langSpans` does not count, the switch markup, the dictionary and its keys, and the resolver's order of URL, stored
choice and `navigator.language`. Anywhere in the repository: the generator of the pages, `hreflang` and sitemap, and
the promotion ticket ([PROMOTION.md](../../../rules/PROMOTION.md) §8) for which locales are meant to be found - in the
ticket store the agent-rules file names, found as the [promote](../../promote/SKILL.md) skill's Step 1 finds it; for a
host with no repository, the hub's ticket. With no ticket, which locales are meant to be found is an owner decision
(INFO). With no repository, read what the live page loads and propose a plan, not a diff.

Budget: 40 fresh requests per site, at most 12 of them language pages, the home's `hreflang` targets first; the rest
goes under "Not measured". The lens writes `<run folder>/i18n.md` and nothing else.

## Inspect

Severity is conventions section 4's; one finding per defect, with the count and the pages. Reach is argued from the
page's own markup and the canon, never from a search result.

1. **Inventory** (`lang`). Per page: per-language URL; in-page blocks (two or more `langSpans` values over 5 elements -
   fewer are the switch's endonyms - or language classes); or a dictionary rewriting one DOM. Count per language and
   name what hides the inactive ones: CSS on `html[data-lang]`, a script, nothing. Nothing hides them (`probe.h1`
   holds two languages): MED. A language page in the served root not live, or live and in neither the root nor the
   generator's output: MED (`source`, conventions section 3).
2. **Required set** (`lang`). EN, RU and UK on every localizable surface
   ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §1): a budget page or page set (guides, help, docs) without one
   of them in any form - its own URL or in-page blocks - is MED, with the count of pages, as is a further locale whose
   text repeats the English page's - a half-translated surface.
3. **The crawler's reading** (`lang`). Quote the first 60 chars of `h1NoJs`; give `lang`, `dataLang`, `h1Count` and
   the Cyrillic share, `cyrillicChars / (cyrillicChars + latinChars)`. One MED per page read as the wrong language:
   `h1NoJs` opening in a language other than `lang`, `h1Count` over 1, or headings repeated per language. On a
   per-language page (its languages have URLs of their own), also `h1NoJs` mixed, or the share over 20% under `en` or
   under 50% under `ru` or `uk` - parity is the language of the visible text, not a file pair
   ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §2); if `probe.cyrRatio` agrees with `lang`, it is wrong for the
   crawler only. On a one-URL page with in-page blocks (LOCALIZATION §3), mixed text is the model; its cost is
   check 4's zero reach, not a second finding. Latin-script languages compare `textNoJs`; `ru` and `uk`, the letters
   only one uses; a code in another script, its own block against Latin under the same 50% line (`\p{IsArabic}` for
   `ar` and `ur`, `\p{IsDevanagari}` for `hi`, `\p{IsBengali}` for `bn`, `\p{IsCJKUnifiedIdeographs}` for `zh`). A
   separate MED: the attribute the hiding rule keys on is not set statically (`PAGE-STYLE` section 6).
4. **Search reach** (`hreflang`). A locale with no URL of its own (in-page blocks, a dictionary, a `?lang=` view that
   canonicalises to the default document - `isParam` - a `noindex` forwarder) is invisible to search
   ([PROMOTION.md](../../../rules/PROMOTION.md) §3):
   one finding for the site per severity, naming the locales. A locale a page declares (`hreflang`,
   `og:locale:alternate`, a sitemap alternate) with no indexable URL of its own: HIGH, it blocks that locale's indexing
   (conventions section 4), fixed by branch A or B. An undeclared one: MED; INFO, citing the line, when the promotion
   ticket states its zero reach as accepted - there a MED is fixed or refused with its reason
   ([PROMOTION.md](../../../rules/PROMOTION.md) §8).
5. **`hreflang` targets** (`hreflang`), on every page. HIGH: a real language page (its text in its language, check 3,
   and not a stub) that is `noindex`, canonicalised away or blocked while the page naming it is indexable. A `?lang=`
   view whose canonical names another URL (`isParam`), a stub (text equal to the default page's - `sameText` for a
   `?lang=` view that names itself - or a page that only forwards - meta refresh or `location.replace` - with no
   content of its own) or a target not answering 200 is no page of its own: check 4's HIGH for its locale, with these
   pages as evidence, and a MED here only where that locale has its own page elsewhere. The contract agrees with the
   first kind (`DOC-EXTERNAL-QUALITY` section 8 items S, T and U list a `?lang=` view only when it is its own
   canonical, so a view canonicalised elsewhere is no alternate). A `?lang=` view that names itself and holds text of
   its own is a page of its own and is judged as any other target; one that names itself and repeats the default
   page's text is a stub whatever its head says, and where the contract lists it the fix names the conflict. MED: not reciprocal
   (a missing return link, or a language version with its own indexable page - a switch target, a sitemap row, a
   language folder in the served root - left out of the set), relative, the page absent from its own set, a code
   twice, a target whose `lang` is not its code, or a code outside ISO 639-1 with an optional ISO 15924 script and
   ISO 3166-1 region (`ua`, `en-UK`; `zh-Hans` and `pt-BR` pass; also as `lang` on any element)
   ([PROMOTION.md](../../../rules/PROMOTION.md) §3; Ukrainian is `uk`, LOCALIZATION §3); `x-default` naming a stub.
   LOW: no `x-default` where alternates exist.
6. **Sitemap rows** (`sitemap`), from `paramUrls`, `alternates`, `problems` and the body, each MED: a `?lang=` row
   whose canonical names another URL (`problems` notes a sampled one; read the canonical of the others), an
   `xhtml:link` alternate naming such a view, or a stub row (canonical URLs answering 200 only, PROMOTION §3;
   `DOC-EXTERNAL-QUALITY` item T - a `?lang=` row that names itself and holds text of its own passes, and
   `paramUrls` only counts the rows to read); a language page meant to be found missing (every public
   page, [DOCUMENTATION_CONCEPT.md](../../../rules/DOCUMENTATION_CONCEPT.md) §3; a `noindex` page, a `CONTEXT-HELP`
   help page among them, stays out - `DOC-EXTERNAL-QUALITY` item O); `xhtml:link` alternates that disagree with the
   page's own set.
7. **Declarations agree** (`lang`, `og`). `<html lang>`, the page's own `hreflang`, `og:locale` and JSON-LD
   `inLanguage` name one language, else MED - on a one-URL page with in-page blocks, `inLanguage` lists the languages
   the page holds, and only a language it does not hold is the MED; `og:locale:alternate` for a locale with no page is
   check 4's HIGH, not a second finding; `og:locale` not `language_TERRITORY` (`en` for `en_US`) or off the portfolio's
   13-language `ll_CC` map ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §3: `en_US`, `ru_RU`, `uk_UA`, `ar_AR`,
   `bn_BD`, `de_DE`, `es_MX`, `fr_FR`, `hi_IN`, `id_ID`, `pt_BR`, `ur_PK`, `zh_CN`, with the regional-variety
   exception `pt_PT` on `epub2html` for European Portuguese text; `cyrflip` `ar_SA` -> `ar_AR` and `epub2html`
   `bn_IN` -> `bn_BD`): LOW; no `lang`: MED; a right-to-left language without `dir="rtl"`: MED
   ([UI_UX.md](../../../rules/UI_UX.md) §6). A finding shared across products (not about one product alone) is asked
   once in the hub's portfolio promotion ticket and cited by every affected product ticket ([SKILL.md](../SKILL.md)
   Step 4).
8. **Rewrites, one source** (`title`, `description`, `content`). Quote the dictionary keys behind `jsRewrites`. Hold the
   static `title`, `description` and strings against the dictionary's entry for that language, and against
   `probe.title` and `probe.metaDesc` (its first 160 characters - ux-probe clips there) where `probe.lang` equals
   `lang`: a difference is two sources drifting ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §3), MED; HIGH when
   they name a different subject or disagree on a name, platform, version, price or release status. A key shown for
   its string: MED; HIGH in the `h1`, title or download control - a missing translation falls back to the source
   language, never to a bare key (LOCALIZATION §1).
9. **Lockstep** (`content`, `version`). Across one page's language versions: one product name in `title` and `h1`
   (one name per concept, UI_UX §4), else MED; `versions` and `links.downloads` agree, else HIGH - a false fact.
10. **The switch** (`lang`, `a11y`), from the markup, `probe.hasLangSwitch`, the tap targets and the screenshot. Several
    languages and no switch: MED, decided from the markup and the screenshot (`probe.hasLangSwitch` is true whenever
    `<html>` carries `data-lang`). An entry to a page not answering 200: HIGH, a dead end. A flag image or emoji, or a
    language named in another language (`German` for `Deutsch`): LOW ([UI_UX.md](../../../rules/UI_UX.md) §5). A bare
    code with no endonym, or `UA`/`ua` for Ukrainian: LOW - the endonym, optionally with its code (UI_UX §5,
    `ICON-EXTERNAL` rule 6), and `uk` on the site toggle (LOCALIZATION §3). A switch that is exactly `PAGE-STYLE`
    section 4.2's `RU` `EN` `UA` gets one LOW per site, and its fix names that conflict - a catalog proposal against
    section 4.2, not a page edit. An entry that is not a link to its existing sibling, or a switch that only writes
    storage, so a shared link opens in the recipient's language: MED. A resolver that lets the stored choice or
    `navigator.language` outrank a URL naming its language (directory, file, query), or `probe.lang` other than that
    URL's `lang`: MED - where `ux_probe.json` has no entry for that URL, judge the resolver from its source or the live
    script and put the rendered half under "Not measured". With a language active, a link to another of the owner's
    sites opens it in that language - its language page, or `?lang=<code>` where that page reads the query
    (`PAGE-STYLE` section 7); a link that drops the language where the stored choice does not reach (another origin:
    `sza.od.ua` and `serzhyale.github.io` are two): MED, a click per hop (conventions section 4). Entries under 48 px
    on the phone (`smallTapTargetsAboveFold`): LOW (UI_UX §2).
11. **A pattern to converge on** (`lang`). The per-language layout a sibling site already serves (its `hreflang`, one
    GET each), a directory per language, `page.<lang>.html` or `page-<lang>.html` files (LOCALIZATION §3,
    `PAGE-STYLE` section 6): INFO; it sets the patch's layout - where siblings differ, the shape most of them serve,
    naming them. The sibling comes from the baseline's host table when the workflow names a baseline, else from the
    hub's product links (`https://sza.od.ua/`, one GET); with neither, "Not measured".

## Propose

Never applied (conventions section 1). A locale that has its own page, or that the promotion ticket names, is meant
to be found: branch A. One the ticket rules out takes branch B. A declaration with no page behind it (a `?lang=`
alternate whose canonical is another URL, an `og:locale:alternate`, a sitemap alternate) is not intent: any other locale gets both branches proposed,
and the report raises the choice as an owner decision (INFO).

**A. Own pages.**
1. One directory or file per language in the layout of check 11, the default at `/` as `x-default`; each with its
   `<html lang>` (and `dir`), `<title>`, description, absolute self canonical, `og:locale` and the full reciprocal
   `hreflang` set with `x-default`, ISO 639-1 codes (`uk`, never `ua`).
2. Each page holds only its own language; the hidden-language spans leave the default page.
3. The existing generator (a build or sync script, a workflow step) renders the pages, `hreflang` and sitemap from one
   dictionary; with none, the minimal script that does ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §3).
4. The switch links to the siblings; choosing Russian, English or Ukrainian writes `sza-lang` (the values of
   `PAGE-STYLE` section 7) before navigating, a further locale is never stored (section 4.2), and the stored choice is
   read on a first visit only.
5. Sitemap: one row per language page, canonical and 200 only, `lastmod` the source file's commit date, no `priority`
   or `changefreq`; alternates in the `<link>` tags or the sitemap ([PROMOTION.md](../../../rules/PROMOTION.md) §3).
6. A moved path stub keeps a meta-refresh and canonicalises to its target; a `?lang=` address, which a static host
   answers from the default file and whose canonical is therefore that file's, leaves `hreflang` and the sitemap
   (`DOC-EXTERNAL-QUALITY` items T and U), and the default page's pre-paint script, which
   reads the query (`PAGE-STYLE` section 7), forwards it with `location.replace` to that language's page, so a link
   shared before the move keeps its language.

**B. One URL, made honest** - in-page blocks are a valid model ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §3).
1. The default language static on `<html>` (`PAGE-STYLE` section 6) and first in source order.
2. No declaration of a locale without its own page: `og:locale:alternate`, `?lang=` alternates and sitemap rows go (a
   view that canonicalises to the page is no alternate, `DOC-EXTERNAL-QUALITY` items T and U). The page keeps
   `hreflang="x-default"` equal to its canonical URL (LOCALIZATION §3; the single-URL form of `DOC-EXTERNAL-QUALITY`
   section 8 item D) and lists the languages it holds in `inLanguage`; on a documentation page that reads the query
   (B.3) whose views name themselves the fix names the conflict with items S and T, as check 5 does for a stub.
3. Static markup and the dictionary's default entry from one source; the switch writes the locale query the page reads
   (`PAGE-STYLE` section 7) into the address.
4. A sentence for the promotion ticket stating each such locale's zero reach.

A unified diff against the named repository file; past about 200 lines (branch A usually is) a numbered plan: the files
created, the generator change, the order, and the check that proves each step.

## Output

Added to the report of conventions section 8; the structured result adds no field:

- After the header, a **Languages** table: code | URL, or the mechanism without one | `lang` | canonical (self, or its
  target) | in `hreflang` | Cyrillic share no-JS / rendered | indexable (yes, or why not).
- In "Proposed patches", each locale's branch and why.
- After them, a **Verification checklist** per language URL:
  `curl.exe -s --max-time 25 -A "Mozilla/5.0 (compatible; sza-site-audit/1; read-only)" <url>` for `<html lang>`,
  canonical and `hreflang`, the script-share command, and what a fixed page shows - its `lang`, a self canonical, the
  full reciprocal set with `x-default`, one language in `h1NoJs`; for a locale kept on one URL, its declarations gone
  and `x-default` and `inLanguage` kept (B.2).

## Canon differences

From the source prompt `site-i18n-one-url-per-language`:

- **One DOM is not always a defect.** In-page blocks are valid ([LOCALIZATION.md](../../../rules/LOCALIZATION.md) §3);
  only a locale meant to be found needs its own URL, otherwise its zero reach is accepted and stated
  ([PROMOTION.md](../../../rules/PROMOTION.md) §3). The source always removed the hidden spans; here the zero reach of
  an undeclared locale is a MED the promotion ticket fixes or refuses (PROMOTION §8), a locale declared with no page of
  its own is HIGH, the patch has two branches, and "one language in the `h1`" binds per-language pages only.
- **Added**: the EN, RU, UK set and the bare-key fallback (LOCALIZATION §1); `hreflang` on every page, not the home
  only (DOCUMENTATION_CONCEPT §3); ISO 639-1 codes with `uk` (PROMOTION §3, LOCALIZATION §3); one source and lockstep
  across languages (LOCALIZATION §3, UI_UX §4); the switch named in its own language, no flag, a 48 px target,
  `dir="rtl"` (UI_UX §5, §2, §6).
- **Switch labels**: `PAGE-STYLE` section 4.2's `RU` `EN` `UA` meet neither UI_UX §5 nor LOCALIZATION §3; the canon
  decides (conventions section 5) and the fix names the contract.
- **"Real page or stub" is the script share of the visible text**, not a file's presence (LOCALIZATION §2); a
  forwarder is a stub whatever its script.
- **Sitemap**: `lastmod` is the source file's commit date, no `priority` or `changefreq`, alternates in `<link>` tags
  or the sitemap (PROMOTION §3); the source asked for a "real" date and sitemap alternates.
- **Retired `?lang=` addresses leave `hreflang` and the sitemap**, which lists canonical URLs answering 200 only
  (PROMOTION §3; a `?lang=` view that canonicalises elsewhere is no alternate, a self-canonical one with text of its
  own is not retired - `DOC-EXTERNAL-QUALITY` items S, T and U); the source's redirect rule becomes a `location.replace` forward in the default page's pre-paint
  script, which reads the query (`PAGE-STYLE` section 7), because a static host answers a query from the default file.
- **Never applied**, not "do not apply without confirmation": a run writes only its git-ignored folder
  ([SITE_CONFIGURATION.md](../../../rules/SITE_CONFIGURATION.md) §7).
